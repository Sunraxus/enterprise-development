# Лабораторная работа 1: Классы - Реализация объектной модели данных и unit-тестов
## Что реализовано
Реализована объектная модель: сущности, связи и перечисления.
* Контрагент (`Counterparty`) — участник сделки: идентификаторы и контакты.
* Недвижимость (`RealEstate `) - объект: тип, назначение, кадастр, адрес и характеристики.
* Заявка (`Application `) - заявка: контрагент + объект + тип операции + сумма + дата.
Перечисления
* Тип объекта недвижимости (`TypeRealEstate`) — какой тип имеет недвижимость при построении.
* Назначение объекта (`PurposeRealEstate `) - под какие нужды будет использоваться объект.
* Тип заявки (`ApplicationType `) - намерение приобрести или продать недвижимость.

## Данные для тестов
Создан класс `TestDataFixture` содержащий:
- 10 контрагентов
- 10 объектов недвижимости
- 15 заявок 


## Unit-тесты
Созданы 5 тестов согласно заданию:
*Тест 1 — поиск продавцов в заданный период: выбирает заявки типа Sale в указанном интервале дат, берет ФИО, удаляет дубликаты и сортирует по алфавиту.
*Тест 2 — топ 5 по количеству заявок: строит два рейтинга отдельно для Purchase и для Sale, группирует по ФИО, считает заявки, сортирует по Count убыванию и по ФИО, берет первые пять.
*Тест 3 — распределение заявок по типам объектов: группирует по RealEstate.Type, считает количество в каждой группе и упорядочивает по числу заявок.
*Тест 4 — клиенты с минимальной суммой: находит минимальное значение Amount и возвращает список ФИО тех, у кого заявки с этой суммой.
*Тест 5 — покупатели по заданному типу: фильтрует заявки Purchase по нужному TypeRealEstate, берет ФИО без повторов и сортирует по алфавиту.

## Результат
Создана объектная модель предметной области с комплексными unit-тестами, покрывающими все требования задания.

# Лабораторная работа 2-3: Классы - Реализация объектной модели данных и unit-тестов
## Что реализовано
В рамках 2-й и 3-й лабораторных работ был реализован сервер на ASP.NET Core для предметной области риэлторское агентство. Приложение с самого начала использует полноценное 
хранение данных в реляционной базе (PostgreSQL) с помощью Entity Framework Core. Хранение в памяти (In-Memory) не применялось. Все данные, контроллеры и сервисы сразу 
интегрированы с базой данных и репозиториями.

###Лабораторная работа 2: Сервер с REST API
## Что реализовано
* Реализованы CRUD-операции для сущностей: объекты недвижимости (RealEstate), контрагенты (Counterparty), заявки (Application).
* Реализовано RESTful API для работы с этими сущностями через отдельные контроллеры.
* В API реализованы аналитические запросы:
*    Получение продавцов по периоду (GetSellersByPeriod)
*    Топ-5 клиентов по количеству заявок (GetTop5CustomersByApplications)
*    Количество заявок по типу недвижимости (GetApplicationCountByEstateType)
*    Клиенты с минимальной суммой заявок (GetClientsWithMinAmount)
*    Клиенты, покупающие объекты определенного типа (GetCustomersByEstateType)
* Вся работа с данными — через Entity Framework Core, миграции и реальные таблицы.


###Лабораторная работа 2: Сервер с REST API
## Что реализовано
* Настроена полноценная ORM-модель с помощью Entity Framework Core.
* Добавлены и применены миграции для создания всех таблиц и связей в базе данных.
* Разработан механизм первичного наполнения (сидирования) базы — автоматическое заполнение тестовыми данными при первом запуске.
* Вся работа с сущностями, аналитикой и CRUD-операциями идет через абстракции репозиториев.
* Добавлен и настроен AutoMapper для преобразования сущностей и DTO.
* Настроен оркестратор Aspire для совместного запуска сервера и базы данных.

## Технологический стек
.NET 8 / ASP.NET Core
Entity Framework Core + PostgreSQL
Репозитории и слой инфраструктуры
Swagger/OpenAPI для тестирования API
AutoMapper, миграции, сидирование, unit-тесты
Оркестратор Aspire

## Архитектура решения
Domain — бизнес-модели, перечисления, абстрактные интерфейсы репозиториев
Infrastructure — реализация репозиториев, контекст EF Core, миграции и сидер
Application — DTO и мапперы (AutoMapper профили)
API — REST-контроллеры, endpoints, swagger

## Результат
Сервер реализован в виде модульного и масштабируемого REST API, сразу интегрированного с базой данных через EF Core. Все бизнес- и аналитические функции вынесены в 
отдельные контроллеры, основное внимание уделено качественному API и удобству написания unit-тестов.


# Лабораторная работа 4: Реализация сервиса генерации данных и его интеграция с сервером через gRPC
## Что реализовано
Создан proto-файл с определением контрактов для gRPC (ApplicationContract, ApplicationsStreamResponse).
Реализован gRPC-сервис на сервере для приёма потока контрактов через Client Streaming.
Сервис валидирует входящие данные, проверяет FK, парсит типы заявок и суммы, сохраняет через репозитории.
Разработан Worker Service (EstateAgency.Grpc.Client) для фоновой генерации и отправки контрактов.
Реализован генератор случайных контрактов с использованием библиотеки Bogus.
Настроена пакетная отправка через Client Streaming: Worker генерирует батч контрактов, отправляет потоком, получает один итоговый ответ с статистикой.
Добавлена retry-логика при недоступности сервера (автоматические повторные попытки с задержкой).
Worker интегрирован в Aspire оркестрацию с автоматической передачей URL сервера через Service Discovery.

## Технологический стек
gRPC (Client Streaming) + Protocol Buffers (proto3)
Worker Service (BackgroundService)
Bogus для генерации тестовых данных
Aspire для автоматической конфигурации

## Архитектура решения
EstateAgency.Grpc.Protos — библиотека с proto-файлами, генерирует классы для сервера и клиента
EstateAgency.Api — gRPC-сервис ApplicationReceiverService для приёма и сохранения контрактов
EstateAgency.Grpc.Client — Worker Service с генератором контрактов и клиентом gRPC
EstateAgency.AppHost — оркестрация с правильным порядком запуска (PostgreSQL → Api → Worker)

Проекты Api и Worker не зависят друг от друга напрямую, используют только общий namespace proto-классов. Связь осуществляется через gRPC по сети.

## Результат
Реализована полноценная микросервисная архитектура с асинхронной потоковой передачей данных. Worker автоматически генерирует реалистичные контракты и отправляет их на сервер 
пакетами. Сервер валидирует, сохраняет в БД и возвращает статистику обработки. Система устойчива к временной недоступности сервера благодаря retry-логике. Всё интегрировано 
через Aspire для удобного локального запуска и отладки.
